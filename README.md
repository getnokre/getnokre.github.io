# getnokre.github.io

The website for [nokre](https://github.com/getnokre/nokre), generated by
nokre.

Not "a site about nokre with a nokre-ish stylesheet". Every page is a
real nokre element tree: a route builder with the same signature an
app's screens have, appending elements through `tree.append`, audited by
nokre's own accessibility audit, and then written out as HTML instead of
pixels. The documentation pages are nokre's own Markdown, expanded by
nokre's own `document` element — not a copy, and not a second parser.

And then the app ships on top of the pages it wrote. The DOM edition has
two drivers — one writes files at build time, one runs the app in the
browser — and this site is both halves of the pair: the file is the
first frame, and the module that boots over it is the same `App` over
the same route table. It has to be, because a build has no font metrics
and no window: `text.Measurer.fixed` answers every measured question
against 1280 pixels, so a nav roster that cannot fit a phone is never
told so. Live, the browser is the ruler and the roster collapses like it
does on every other platform.

Nothing waits for it. The markup is complete before a byte of script
arrives, every link is a real link to a real file, and JavaScript off
leaves you the 1280-pixel reading of the page rather than an empty one.

`docs/internals/renderer-editions.md` left this door open on purpose:

> A renderer is an *interpretation* of the semantic tree, the way a
> browser interprets HTML. It may draw each element however it likes,
> with capabilities the Skia edition refuses, so long as the semantics —
> element set, behavior, focus model, a11y tree — are conveyed
> faithfully.

`/colophon/` is the long version, including the two places this
edition stops short.

## Build

Needs Zig 0.16 and a nokre checkout beside this one:

```
../nokre
./getnokre.github.io
```

```sh
zig build site                 # writes docs/ — the published tree
zig build site -Dout=preview   # …somewhere scratch instead
zig build site -Drepo=/path/to/nokre
zig build test                 # the generator's own unit tests
python3 -m http.server -d docs 8000
```

A caveat on `-Drepo`: `b.dependency("nokre")` resolves through
`build.zig.zon`'s `.path = "../nokre"` regardless — the flag redirects
only the docs and live.js/services.js reads — so it must point at the same
checkout the zon path names; passing a different one builds against one
library and renders the other's docs.

The build fails, rather than publishing something wrong, when:

- a route name is duplicated or malformed (`App.init` validates the
  table);
- a screen fails nokre's accessibility audit — a skipped heading level,
  an unlabeled control, two controls sharing a label, a text/ground pair
  outside the contrast floor or ceiling;
- a reference in any document names a page this site does not publish,
  an anchor no heading on the target page has, or a source file that is
  not in the repository;
- an element has no case in the edition's writer — the set is closed
  there too, and the switch has no `else`.

## Layout

| Path | What it is |
| --- | --- |
| `src/pages.zig` | The route table: one flat name per screen, and its title, blurb and glyph. |
| `src/content.zig` | Every screen this site adds, as nokre trees. No templates and no HTML. |
| `src/links.zig` | The site's `dom.Refs`: what a document's `[label](dest)` points at, recorded for the link check. |
| `src/main.zig` | The static driver: the app, the audit, the page shell, and the files it writes. |
| `src/web.zig` | The live one: the same app, as a wasm module, with the three decls nokre's live driver looks for. |
| `src/shell.zig` | The one C hook every non-test build links. This generator is a platform shell; the wasm module is not. |
| `tools/build-fonts.py` | Subsets nokre's bundled faces into the woff2 files in `assets/fonts/`. |

## Fonts

`assets/fonts/*.woff2` are nokre's own bundled binaries — IBM Plex Sans,
JetBrains Mono, Lucide, Vazirmatn — subset to what this site draws and
repackaged as woff2. Their upstream licenses are beside them.
Regenerate after a font change in nokre:

```sh
python3 -m venv .venv && .venv/bin/pip install fonttools brotli
.venv/bin/python tools/build-fonts.py ../nokre
```

## Publishing

The site is built **locally** and committed. There is no CI: GitHub
Pages is set to *Deploy from a branch* — `main`, folder `/docs` — so it
serves the committed tree as it stands and runs nothing.

```sh
zig build test && zig build site
git add docs && git commit -m "Rebuild"
git push
```

The colophon stamps provenance at build time — each checkout's commit
(short hash) and a "with uncommitted changes" marker when its tree is
dirty — so the order matters: **commit nokre first, then rebuild, then
commit here.** A rebuild over a dirty tree writes that admission into
the page it publishes. And the site's own stamp is HEAD *as of the
build*: the commit that publishes a rebuild is by construction one
ahead of the hash on its colophon. That is honest, not broken — no page
can carry the hash of the commit that contains it.

`docs/` holds the pages, the generated stylesheet, the faces, each
document's Markdown (`docs/md/` — what a live page seeds itself from),
and the two build outputs of the live half: `app.wasm`, and nokre's own
`live.js` + `services.js` copied from the checkout. A committed binary,
because the published tree *is* the site: there is no build running
anywhere but here.

`git diff --stat docs` before committing is the review: the generator is
deterministic, so the only lines that move are the ones something
actually changed. Rebuild after a change here **or** in nokre — the
documentation pages are rendered from that repository at build time, so
a docs change there is only on the site once someone rebuilds.
